Firewalls, VPNs & Proxies: What Each One Actually Filters

These three mechanisms are often lumped together because all can sit 'in the middle'. Their jobs differ. A firewall enforces traffic policy, a proxy relays application-level or other traffic on behalf of a client, and a VPN creates an encrypted tunnel between endpoints or networks. Understanding what information each can see is the key.

These three mechanisms are often lumped together because all can sit 'in the middle'. Their jobs differ. A firewall enforces traffic policy, a proxy relays application-level or other traffic on behalf of a client, and a VPN creates an encrypted tunnel between endpoints or networks. Understanding what information each can see is the key.

MENTAL MODEL

Remember the shape, not the sentence

“A firewall is a security gate, a proxy is an intermediary receptionist, and a VPN is a private tunnel through a public building.”
01

Firewalls

A firewall can filter using addresses, ports, protocols, state and application context depending on its design. Stateful firewalls track connection state so return traffic can be handled differently from unsolicited packets.

02

Proxies

A forward proxy acts on behalf of clients. A reverse proxy acts on behalf of servers and can provide TLS termination, load balancing, routing, caching and access control.

03

VPNs

A VPN encapsulates traffic inside a tunnel that provides confidentiality/integrity and a virtual network relationship. Encryption alone does not guarantee that every destination or endpoint is trustworthy.

STEP BY STEP

Walk the system

01

Firewall

Observe packet/flow attributes and apply allow/deny policy.

02

Forward proxy

Client sends traffic to an intermediary that makes the outbound request.

03

Reverse proxy

External clients reach an intermediary that selects an internal backend.

04

VPN

Endpoints encapsulate traffic through an encrypted tunnel.

05

Policy

Security still depends on identity, routing, endpoint controls and application authorization.

CONCRETE ARTIFACT

Choose by visibility

The most useful question is not 'where is the box?' but 'which endpoint terminates the protocol and what metadata can it inspect?'

MISCONCEPTIONS

What usually goes wrong

Call every intermediary a proxy.

Assume a VPN automatically makes every application secure.

Assume a firewall can always see encrypted payload contents.

RETRIEVAL PRACTICE

Close the tab. Rebuild it from memory.

Read the question, answer aloud, then reveal.

What is a reverse proxy?Reveal answer

An intermediary that represents backend servers to clients and can terminate TLS, route requests, balance load and enforce policy.

What does a stateful firewall add?Reveal answer

It can make decisions based on connection state, not only isolated packets.

What does a VPN fundamentally provide?Reveal answer

A protected tunnel between tunnel endpoints, carrying encapsulated traffic over another network.

FEYNMAN

Teach it back in plain English

Draw the same web request with no intermediary, a forward proxy, a reverse proxy and a VPN. Mark which component terminates which protocol.

EXAM / INTERVIEW

What a strong answer sounds like

Expect role-comparison questions and scenarios asking which intermediary sees a port, HTTP path, client identity or encrypted payload.
